# ADR-002: Выбор архитектуры ИИ-классификатора отзывов болельщиков

- **Статус:** Принято (Accepted)
- **Дата:** 2026-11-19
- **Автор:** Әділ Шаяхметов (PM) / Команда «Express»
- **Связанные задачи:** `EXP-28`, ЛЗ-12

## Контекст и постановка проблемы

Во время матчей через веб-систему предзаказа **«Express»** проходит до 2 000 заказов, после которых болельщики оставляют текстовые отзывы на русском и казахском языках. Менеджменту фуд-корта и команде разработки необходимо оперативно маршрутизировать обращения по 4 категориям:
1. `Food Quality` — качество и температура блюд (фуд-корт);
2. `Payment Issue` — сбои оплаты Kaspi QR и возвраты (бухгалтерия / поддержка);
3. `App Bug` — дефекты интерфейса и отображения кода выдачи (Front/Back);
4. `Staff` — качество обслуживания на стойках выдачи (администратор смены).

При этом отзывы часто содержат персональные данные (ПДн): номера телефонов (`+7 701 ...`), email-адреса и имена, которые запрещено передавать в сторонние облачные LLM в открытом виде.

## Рассмотренные варианты

### Вариант 1: Ручная разметка отзывов в Excel
- **Плюсы:** Отсутствуют затраты на API и инфраструктуру; нулевой риск утечки ПДн во внешние облака.
- **Минусы:** Высокие трудозатраты PM/менеджера после каждого матча; задержка реакции на критические баги оплаты (`Payment Issue` / `App Bug`) составляет 1–2 дня.

### Вариант 2: Локальная модель Llama 3 8B на арендованном GPU-сервере ($80/мес)
- **Плюсы:** Полная локализация данных внутри периметра; нет платы за токены.
- **Минусы:** Стоимость аренды GPU ($80/мес ≈ 39 000 ₸/мес) превышает годовой лимит бюджета MVP по TCO; требуется дополнительное DevOps-сопровождение (мониторинг VRAM, обновления весов).

### Вариант 3: Облачный API `gpt-4o-mini` с предварительной очисткой ПДн ($0.75/мес)
- **Плюсы:** Минимальная стоимость владения (~$0.75/мес при 5 000 отзывов); высокая точность классификации на русско-казахском билингвальном тексте; отсутствие затрат на GPU-инфраструктуру.
- **Минусы:** Зависимость от внешнего API; требуется обязательный детерминированный слой очистки ПДн перед отправкой запроса.

## Принятое решение

Выбран **Вариант 3**: облачная классификация (`gpt-4o-mini` + локальный детерминированный fallback) с обязательной предварительной очисткой персональных данных через серверный модуль **`EXP-28`** (`scrub_pii()` в `backend/main.py`).

### Требования безопасности и контроля качества (AI Governance)
- Все номера телефонов маскируются в `[PHONE_REDACTED]`, а адреса электронной почты — в `[EMAIL_REDACTED]` **до** логирования, сохранения в БД и отправки в ИИ-модель.
- Валидация качества выполнена на эталонном датасете `docs/ai/eval_dataset.csv` из 30 размеченных отзывов: **27 Pass / 3 Fail**, итоговая метрика **Accuracy = 90.0%** (превышает целевой порог 85%).

## Последствия

- **Положительные:** Автоматическая сортировка жалоб в реальном времени при затратах менее $1/мес; соответствие требованиям защиты ПДн (`EXP-28`).
- **Отрицательные / Риски:** В 10% пограничных случаев (смешанные жалобы, например «зависло приложение при оплате» или «грубый кассир отдал холодный бургер») требуется ручная перепроверка ответственным менеджером.
